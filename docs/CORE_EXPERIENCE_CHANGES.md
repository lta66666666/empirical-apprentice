# 一键示范、Stata 简化与同步教学：优化说明

## 本轮改动

| 原问题 | 修改与实际行为 |
| --- | --- |
| 案例只填部分资料，仍不断追问 | 分析空白页增加“一键体验同批 DID”；先保存草稿，再新建独立练习，服务端一次填入数据摘要、字典、来源、研究资料和方案。原有另两例也复用完整初始化。 |
| 固定效应与 DID 共用数据，哈希不能判断案例 | 分别保存案例 ID、固定版本、输入哈希；任务使用归属练习中的显式案例身份，方法单独记录。 |
| Stata 需要手动下载文件和填路径 | 新助手包内附带现有三份模拟资源及哈希清单。配对后明确点击准备，助手复制到专用目录并同步摘要；不会执行估计。 |
| 换配对可能带上旧输入 | 输入绑定配对与练习；新配对清空当前选择和展示。轮询使用配置快照，迟到心跳不能修改新配对。旧文件、复现包保留。 |
| OLS 残留面板字段影响样本 | 前后端使用相同方法角色规范化：OLS 清除个体／年份，非 DID 清除处理组与政策条件，非聚类设置清除聚类列。 |
| 无关设置过多 | 本机表按三种方法显示必要字段；连接成功后收起连接设置，方差、缺失、桥接器和对照放“更多设置”，最终摘要显示实际设置。 |
| 左侧讲解停留在旧命令 | 字段、模型、任务及实际估计项统一触发教学更新；具体 Stata 命令仍绑定已保存预览，迟到响应按完整上下文拒绝。完整阅读窗口不会被后台刷新。 |
| 正确回答仍被要求改同义措辞 | 新增结构化评价；实际数值一致及合理四舍五入不作为数值错误，可选建议单列。无证据反馈显示未确认。 |

## 使用路径

1. 登录 → 边分析边学 → 一键体验同批 DID。
2. 默认浏览器 R：核对方案 → 勾选确认 → 执行。
3. 学 Stata：改用本机 Stata → 在此示范练习配对 → 在助手准备模拟数据 → 核对提交。
4. 点击网页实际代码学习；在本机批准完整代码，计算后另行批准上传摘要。
5. 点击实际统计量学习，提交自己的解释，按需修订及下载报告。

阅读、案例载入和准备文件均不批准计算。未知物理单位不阻止普通有效回归；DID 的结构、批次与实施年份仍须有效。内置案例仅为模拟，不能认证真实政策效应。

## 接口及兼容

- `POST /api/sessions` 增加可选 `fixture_id / fixture_version / request_id`，普通新练习兼容；案例创建与草稿、幂等回执使用事务。
- `POST /api/local-stata/pairings/prepare-fixture` 创建固定案例准备请求，复用心跳回执，独立于计算任务。
- `analysis-context` 草稿只保存明确的执行软件，不改变研究版本。
- 正式解释增量增加 `assessment`；旧反馈字段和历史记录保留，报告读取同一次持久版本。
- 增量迁移 `0008_demo_creation.sql` 仅增加示范幂等与准备回执表，不改写原账号、任务或成果。

## 边界

仍是现有 OLS、个体＋年份固定效应、同批 DID。没有新增估计方法、真实案例、测验、云端 Stata 或部署迁移。Python 标识与 Stata 分开，保留本机两次批准。助手包为源码及固定模拟资源，仍需按说明准备运行环境和有效 Stata 安装。
