## 精简与补缺说明

| 原问题 | 本轮修改 |
|---|---|
| 核对和结果需反复开弹窗，输入与讲解被隔开 | 将保留的操作控制器移入中央当前卡，可收起；输入保持在布局中。模拟任务恢复后可直接打开任务卡 |
| 右侧摘要也承担多组操作 | 右侧保留资料、数据、结果状态与资料详情；操作按钮由中央承担 |
| 上传后代用户发言并调用模型 | 数据与政策材料保存后直接反馈检查结果；数据进入字段核对，用户提问才请求AI |
| 默认展示执行环境细节 | 执行环境默认折叠为“更多执行方式”，原有备用和本机批准控制保留 |
| 点击代码后需要关闭窗口看讲解 | 在代码卡内提供就近说明与详细讲解，同时更新左侧知识；窄屏不自动弹出侧栏遮住代码 |
| 独立重跑重试会新建多个任务 | 请求编号绑定原任务/输入/方案指纹，使用现有数据库唯一约束；并发或响应丢失重试返回同一任务，配额按账号归属累计 |
| 失败恢复降为普通CSV | 优先读取原材料，保留 `data_id`、原文件名、标签、日期、转换出处与任务字典；旧无材料编号任务保留文本兼容 |
| DID核对通过后才发现个体没有前后期 | 在删除选定列缺失后的完整样本中检查逐个体前后期与四格，不自动删除个体 |
| 教学固定声称StatsPAI计算完成 | 从持久方案/任务读取软件和状态，区分拟执行、未完成和完成；未知软件不猜测 |
| 问DTA导入、删了几行却命中无关内容 | 补充跨软件导入说明、自然问法匹配；显式Stata学习目标优先于Python计算上下文，无文字关联材料不靠阶段加分强行推荐 |
| 对应代码来源一律为OLS帮助 | 按命令主题链接xtreg、xtset、import delimited、destring及缺失说明；结果讲解读取任务字典，不猜单位 |
| 阅读位置只保存不恢复 | 按持久代码哈希、任务或确认引用恢复命令；请求仍受账号、版本、序号校验。页面位置单独使用只读草稿 |
| README混杂多代默认方式 | 首页文档保留当前候选与体验入口；历史记录移入 `HISTORY_ARCHIVE.md` 并调整相对链接 |

源码未增加方法、测验、成绩或掌握认证。计算模板与已有推断范围保持原有配置。

先在本机预览验证：导入CSV/DTA→字段核对→方案→点击对应代码→确认→结果→解释两次修订→实际下载报告与复现包；再验证失败恢复与刷新。最终截图、原文件/规范化哈希、任务及结果版本一并保存。浏览器审批服务恢复后补齐真实证据，再将对应待验项更新为通过。

预览启动：项目目录运行 `node scripts/build-prototype.mjs` 后运行 `node scripts/preview-experience.mjs`，打开 `http://127.0.0.1:18843/`。预览和HTTP回归都使用8000执行端口，应先停止预览再运行回归，避免端口冲突。
