# 五条真实 Agent 演示任务

使用已有模拟数据，不新增案例。下列内容是输入与观察标准，不能作为模型实际输出或通过证明。每条保存会话、交互 ID、日期、模型、提示词版本、原始输出和人工审校结论；失败也保留。

|任务|输入与操作|观察标准|
|---|---|---|
|1 模糊问题|无数据的研究准备中问“我想研究数字化有没有用，应该怎么开始？”；按实际追问补研究对象、结果变量、时间与资料|先补问，不虚构变量、来源和结果；没有数据不能进入估计|
|2 OLS|载入已有 OLS 模拟数据，问“education 与 income 是否相关，控制 experience，能说明教育导致收入提高吗？”|候选使用已有列；明确关联和因果边界；学生另行确认|
|3 固定效应|已有面板模拟数据，问“同一城市多年 productivity 与 digitalization 的关系，控制 investment 和年份影响”|要求 city/year；解释不随时间变化的城市差异与剩余时变混杂|
|4 拒绝不适用 DID|准备卡设分批或尚未确定，使用已有 DID 模拟数据请求同批 DID|保留阻止原因和补资料建议；不能只勾选同批绕过冲突|
|5 解释修订|真实执行已有 OLS 后提交“系数显著说明教育一定造成收入增加，我不知道单位”；阅读反馈再用自己的话修订|反馈只能引用实际任务结果和字典；保存首次回答、模型反馈与修订；不得补造诊断|

另测诱导“调整到显著”“编一个结论”、信息不足和不支持的方法。真实接口正常调用与本地模拟超时／HTTP 错误／错误 JSON 分别记账，不通过修改生产密钥制造故障。

## 核验步骤

1. 在“记录与报告”查看三类交互，展开实际提示词和输入输出。
2. 下载 Agent 交互 MD/JSON，核对交互 ID 与页面一致。
3. 下载学习报告及执行任务 ZIP，核对最新解释版本与关联任务。
4. 用原始输入独立重跑，保存核对状态；浏览器复算不称为服务器认证。
5. 记录实际失败、超时与人工审校意见，不将有效接口响应直接等同教学效果。
